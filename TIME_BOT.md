# Бот в Time — спека

Спека. Первые два пункта из «порядка работ» внизу **уже написаны** — что именно работает,
рассказано в [README.md](README.md), раздел «Сообщения в Time». Здесь остаётся то, чего
ещё нет, и решения, по которым это сделано. Когда список работ закончится, файл уйдёт.

Чего хотим:

1. Каждый открытый PR — сообщением в канал Time. Любой: обычная карточка, сабтаска эпика,
   спека эпика. Без исключений.
2. В тред этого сообщения человек пишет, что поправить, — фабрика правит.
3. Секреты и канал настраиваются через окно приложения, а не правкой файлов.
4. Однажды фабрика переедет на сервер, и переезд не должен ломать пункты 1–3.

---

## Из этого сразу следует: нужен бот

Incoming webhook двусторонний сценарий не закрывает: он умеет только писать. Тред создать
не может (в его теле нет `root_id`), id своего сообщения не возвращает, читать канал им
нельзя вообще. Значит нужен токен — и раз токен всё равно нужен для чтения, писать тоже
логично им.

- **Bot Account** — то, что нужно: токен не протухает, в канале видно «Фабрику», а не
  человека. Создаётся в Time (Integrations → Bot Accounts), и пункт этот появляется только
  когда администратор включил в System Console *Enable Bot Account Creation*. Просить надо
  ровно это.
- **Личный токен** (`/time-login`) — работает без администратора, но живёт считанные дни
  и требует интерактивного входа. Для сервера не годится по той же причине, по которой
  не годится подписочная сессия `claude` (см. ниже).
- **Вебхук** — остаётся как урезанный режим: оповещения идут, правки по треду не работают.
  Это осмысленное состояние, а не заглушка: до появления бота фабрика уже полезна.

Поэтому в конфиге есть `transport`, и код обязан работать в обоих режимах.

## Что бот делает

### Сообщение на каждый PR

Отправка живёт **внутри `open_pr`**, а не у вызывающих. Сейчас `open_pr` зовут из двух
мест (обычный поток и спека эпика), завтра появится третье — и его забудут подключить.
Одна точка, из которой нельзя не отправить.

Сообщения нет там, где нет нового PR: на круге «Правки» фабрика пушит в ту же ветку,
`open_pr` возвращает уже открытый PR. Обновления по такой задаче идут ответами в тред,
а не новым сообщением в канал.

В сообщении: карточка (номер, заголовок, ссылка), PR, ветка, одна фраза о том, что сделал
агент (тот же подрезанный `summary`, что уходит в карточку), для сабтаски — ссылка на эпик.
Список запущенных проверок — нет: он не пишется даже в карточку, потому что её мусорил.

Корень треда запоминается: `state/time.json`, `card_id → {channel_id, root_id, last_post_id}`.

### Ответ в треде → правка

Главное решение: **тред — это второй вход в существующую машину, а не новая машина.**
Источник правды остаётся Kaiten.

На своём тике фабрика читает треды, которые сама создала, берёт сообщения новее
запомненного `last_post_id`, свои отличает по `user_id` бота. Человеческое сообщение →
комментарий в карточку (с именем автора) → карточка уезжает в «Правки».
Дальше всё как сейчас: исполнитель, ревьювер, тот же PR в той же ветке. Итог возвращается
ответом в тот же тред и комментарием в карточку.

Почему через карточку, а не сразу в агента: у карточки уже есть машина состояний, счётчик
кругов, стоп-фраза, бюджет, ночной тег. Прямой путь «сообщение → агент» всё это
продублировал бы и через месяц разъехался с оригиналом.

Опрос, а не входящий вебхук: фабрика — пакетный процесс по расписанию, принимать входящий
HTTP ей некуда. На сервере можно будет добавить outgoing webhook или WebSocket и реагировать
сразу, но опрос останется — он же и восстановление после простоя.

### Кто имеет право командовать

Ответ в треде запускает агента, который пишет код и пушит ветку, а канал шире доски:
в доску пишут те, кто её ведёт, в канал — все.

- `allow_from` — список username. Пусто — любой участник канала.
- Текст из треда — **данные, а не команда фабрике**. Он едет в карточку как постановка
  задачи; колонку, ветку, бюджет и число кругов фабрика решает сама. Сообщение вида
  «смержи без ревью» остаётся текстом задачи, а не инструкцией.
- Стоп-фраза работает и здесь.

### Чего бот не делает

Не мержит PR, не двигает карточки по просьбе из треда, не пишет в каналы, где его нет,
и не пересказывает в Time то, что уже есть в карточке и в PR: круги ревью — там, в тред
только итог.

## Конфиг

```json
"notify": {
  "time": {
    "transport": "bot",
    "base_url": "https://<company>.time-messenger.ru",
    "channels": { "default": "<channel_id>", "kiosk": "<channel_id>" },
    "events": ["pr_opened", "pr_updated", "fix_taken"],
    "allow_from": [],
    "follow_threads": true
  }
}
```

Канал — по репозиторию, как `repos`: два проекта в один канал сваливать незачем. Список
событий настраивается, потому что «каждый PR» и «каждая мелочь» — разные желания у разных
команд. Пока их три: `pr_opened` — новый PR корневым сообщением, `pr_updated` — правка
ответом в тот же тред, `fix_taken` — подтверждение, что сообщение из треда доехало
до карточки. `needs_human`, `failed` и `auth_broken` — в списке работ ниже. Секретов
в конфиге нет.

## Где живут секреты

Порядок поиска один на всё: **переменная окружения → Keychain → `.env`**.

- На маке окно настроек пишет в Keychain (`security add-generic-password`), а не в файл:
  токен в открытом виде на диске — то, чего в публичном репозитории не должно появиться
  даже случайно. `setup.py --audit` это поймает, но полагаться на аудит вместо того, чтобы
  не создавать файл, — плохая сделка.
- На сервере Keychain нет: переменная окружения из systemd или секрет-менеджера.
- `.env` третьим — так сейчас читается `KAITEN_TOKEN`, ломать не надо.

Одна функция `resolve_secret(name)` обслуживает оба мира. Это же снимает половину вопроса
про переезд: конфиг файлом, секреты окружением — то, что сервер и ожидает.

## Окно настроек

Сейчас окна нет вообще: 951 строка AppKit, `NSMenu`, три интервала в `UserDefaults`.
Значит новое окно (AppKit-форма или SwiftUI через `NSHostingView`), а в нём:

- транспорт, `base_url`, токен или URL вебхука — в `NSSecureTextField`;
- канал **списком, а не строкой**: с токеном приложение само дёрнет команды и каналы бота
  и покажет выбор. В режиме вебхука поля канала нет — он зашит в URL;
- галки событий и `allow_from`;
- кнопка «Проверить»: посылает тестовое сообщение и показывает результат. Сразу видно
  и права, и от чьего имени приходит — тег BOT и то, включено ли в System Console
  переопределение имени.

**Правило, без которого переезд сломается: окно — надстройка над `config.json` и хранилищем
секретов, а не отдельный источник правды.** Всё, что задаётся в окне, должно читаться
и из файла. `UserDefaults` для настроек фабрики не годится по той же причине — три интервала
попали туда до того, как сервер появился в планах, и их придётся переносить.

## Что доработать для сервера

Уже не про бота, но бот на это опирается.

1. **Расписание.** Планировщик сейчас — приложение: закрыл его, и фабрика встала.
   На сервере — systemd timer по тем же флагам (`--only-triage`, `--only-review`,
   `--only-work`). Работы почти нет: фабрика уже CLI.
2. **Замок на прогон.** Его нет. `state/status.json` держит `pid`, но второму прогону никто
   не мешает начаться. На маке спасало то, что запуск один и из приложения; cron наступит
   на это в первую же неделю. Нужен `flock` на файл.
3. **Авторизация `claude` — самое дорогое.** Сейчас агент идёт под подпиской claude.ai:
   сессия живёт считанные дни, продлевается интерактивным входом (фабрика уже умеет
   распознавать её смерть и показывать кнопку). На сервере интерактивного входа нет →
   `ANTHROPIC_API_KEY` и оплата по токенам вместо подписки. Это меняет экономику прогона,
   а не только конфиг.
4. **Секреты** — порядок поиска выше.
5. **`gh` и git.** PR создаётся через `gh`: нужен `GH_TOKEN`, ssh-ключ для пуша ветки
   и `user.name`/`user.email` для коммитов агента.
6. **Окружение.** Прогон стартует через `zsh -ilc`, чтобы доехали nvm-node и токены
   из профиля. На сервере профиля нет: версия node и переменные задаются явно, механизм
   для этого — `pass_env` — уже есть.
7. **Наблюдаемость.** На маке состояние читает менюбар из `state/status.json`. На сервере
   его не читает никто, и сообщения в Time становятся единственным способом узнать, что
   происходит. Поэтому бот — часть плана переезда, а не украшение: `failed`, «протухла
   авторизация», «разведка сорвалась» обязаны уезжать в канал.
8. **Рестарты.** Прогон, убитый на середине, оставляет карточку в «В работе»; сейчас это
   лечится руками. На сервере — деплой, перезагрузка — это станет регулярным: нужен возврат
   зависших карточек по времени в колонке.
