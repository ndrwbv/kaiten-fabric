# Установка

Фабрика берёт задачи с доски в Kaiten, делает по ним изменения в твоём репозитории и
открывает черновые PR. Что она делает и почему именно так — в [README.md](README.md).
Здесь только установка: минут двадцать, из них пятнадцать — ожидание первого прогона.

Если лень читать — отдай эту инструкцию агенту: `claude` в этой папке, дальше
[«Установка руками агента»](#установка-руками-агента).

---

## 1. Что нужно иметь

| Что | Как проверить | Если нет |
|---|---|---|
| macOS | | фабрика ходит в keychain и меню-бар, на Linux не проверялась |
| Python 3.10+ | `python3 --version` | ставится с Xcode Command Line Tools |
| Claude Code | `claude --version` | [claude.com/claude-code](https://claude.com/claude-code) |
| GitHub CLI | `gh auth status` | `brew install gh && gh auth login` |
| Git | `git --version` | `xcode-select --install` |
| Токен Kaiten | | Kaiten → аватар справа сверху → Профиль → API-ключ |
| Локальный клон рабочего репозитория | | обычный `git clone`, фабрика его не тронет |

Подписка на Claude — своя, обычная. Фабрика запускает `claude -p` от твоего имени,
отдельного API-ключа не нужно.

## 2. Забрать фабрику

```bash
git clone git@github.com:ndrwbv/kaiten-fabric.git ~/work/kaiten-fabric
```

Папку можно положить куда угодно — путь никуда не зашит, кроме собранного приложения
(его после переезда надо пересобрать).

---

## 3. Запустить мастер

```bash
cd ~/work/kaiten-fabric && python3 setup.py
```

Мастер спросит по шагам и сам найдёт все id — руками в API лазить не нужно.

**Токен.** Спросит `KAITEN_TOKEN` и домен, положит их в `.env` рядом со скриптом
(права 600, файл в `.gitignore`). Если токен уже лежит в `~/.claude/.env` — возьмёт оттуда
и переспрашивать не станет.

**Пространство.** Пространств в компании сотни, поэтому мастер ищет по куску названия
и показывает найденное списком.

**Рабочая доска.** Тут два пути:

- **создать новую** — мастер заведёт доску и разложит на ней восемь колонок в правильном
  порядке. Это рекомендуемый путь: названия и типы колонок он проставит сам;
- **взять существующую** — тогда он покажет её колонки и разложит их по ролям, угадывая
  по названиям. Что не угадает — переспросит.

Восемь колонок — это и есть поток карточки:

| Колонка | Что означает |
|---|---|
| Очередь | фабрика берёт карточки отсюда |
| В работе | агент пишет код |
| Вопрос от агента | не хватило данных, ждём ответа человека |
| Упало | агент или обёртка сломались |
| Ревью агента | готовый PR, отсюда его берёт ревьювер |
| Правки | ревьювер вернул замечания |
| На ревью | ревью пройдено, дальше смотрит человек |
| Готово | фабрика сюда ничего не двигает |

Названия могут быть любыми — важны только роли. Двигать карточки руками между колонками
можно и нужно: так с фабрикой и разговаривают.

**Инбокс — по желанию.** Отдельная доска, куда команда скидывает баги и идеи как есть.
Разведчик читает новые карточки и пишет комментарий: о чём задача, где это в коде и
хватает ли данных. Чужие карточки он не двигает и не правит. Мастер спросит, включать ли,
и если да — попросит выбрать доску и колонку. Скажешь «нет» — секции `inbox` в конфиге
просто не будет, и фаза не запустится.

**Доска эпиков — по желанию.** Если включить, раз в спринт заводится карточка
«Долг \<даты спринта\>», и всё сделанное вешается на неё дочерними. Удобно, когда надо
показать поток в отчётах. Скажешь «нет» — привязки не будет.

**Репозиторий.** Путь к локальному клону, remote и базовая ветка. Свою рабочую копию
фабрика не трогает: на каждую карточку она делает отдельный `git worktree` у себя внутри.

## 4. Написать правила проекта

Мастер создаст `project/docs.md` и `project/checklist.md` из примеров. Это единственное
место, где живёт что-то специфичное для твоего проекта:

- **`project/docs.md`** — какие файлы правил агент обязан прочитать до того, как писать
  код. Пути в обратных кавычках и одна фраза «что там». Ссылайся только на то, что реально
  лежит в репозитории;
- **`project/checklist.md`** — по какому списку исполнитель проверяет себя перед коммитом,
  а ревьювер потом ревьюит. Список один на двоих намеренно: иначе они разъезжаются, и
  ревью превращается в спор о вкусах.

Оба файла можно оставить пустыми — фабрика заработает, но агенты будут опираться на общие
соображения, а не на ваши договорённости. Качество ревью держится ровно на подробности
этих файлов: **правило, которого нигде не написано, соблюдаться не будет.**

Файлы в `.gitignore` — внутренние договорённости в общий репозиторий не уедут.

## 5. Проверить и запустить

```bash
python3 setup.py --check
```

Доктор проверит: инструменты на месте, токен рабочий, доска и все восемь колонок
существуют, репозиторий на месте, правила проекта заполнены. Он же скажет, что именно
чинить, если что-то не так.

Дальше — прогон вхолостую: агент отработает по-настоящему, но в Kaiten и GitHub ничего
не запишет.

```bash
./run.sh --dry-run
```

Положи в «Очередь» одну простую карточку и посмотри, что получится. Первый прогон стоит
смотреть целиком: понятно ли агенту описание, туда ли он полез, что написал в комментарии.

Когда доверия хватит:

```bash
./run.sh
```

Полезные флаги: `--card <id>` — прогнать конкретную карточку, `--limit 1` — взять одну,
`--prompt-only` — показать промпт и выйти, ничего не запуская.

## 6. Приложение в меню-баре

Чтобы фабрика ходила на доску сама, по расписанию:

```bash
./build-app.sh --install
```

Собирает приложение и кладёт в `/Applications`. В меню-баре появится человечек: там
расписание, что происходит прямо сейчас и стоп-кран. Закрыл приложение — фабрика
перестала ходить на доску. Подробности и автозапуск — в [README.md](README.md).

## Установка руками агента

В папке фабрики лежит [AGENTS.md](AGENTS.md) — инструкция для агента. Запусти в этой
папке `claude` и скажи:

```
Установи фабрику по AGENTS.md
```

Агент прочитает инструкцию, соберёт конфиг через `setup.py`, проверит доктором и
предложит первый прогон. Токен он спросит у тебя — сам его нигде не берёт.

## Если что-то не так

| Симптом | Что делать |
|---|---|
| `KAITEN_TOKEN не найден` | `python3 setup.py` спросит и положит в `.env`; проверить: `cat .env` |
| `HTTP 401` от Kaiten | токен протух или скопирован не целиком — перевыпустить в профиле |
| `CERTIFICATE_VERIFY_FAILED` | не должно случаться: фабрика ходит через `curl`, а не через python. Если всё-таки — корпоративный прокси, смотри системное хранилище сертификатов |
| `claude` не стартует | запускать из обычного терминала: внутри сессии Claude Code он не стартует намеренно |
| `gh: не авторизован` | `gh auth login` |
| Колонка не нашлась | `python3 setup.py --board <id>` покажет все колонки с id, дальше поправить `config.json` руками |
| Агент отработал, но проверок не запустил | не доехала переменная из `pass_env` — проверь, что она есть в `~/.zshrc` |

Полная таблица ошибок — в конце [README.md](README.md).

## Перед тем как что-то коммитить

В репозиторий не должно уехать ничего внутреннего: ни id досок, ни путей с твоим именем,
ни правил проекта. За этим следит `.gitignore`, а проверить можно так:

```bash
python3 setup.py --audit
```

Аудит смотрит файлы, которые git собирается закоммитить, и ищет в них то, что лежит
в твоём локальном конфиге, плюс общие вещи вроде почт, токенов и домашних путей.
