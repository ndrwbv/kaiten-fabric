# Инструкция для агента: установить фабрику

Ты ставишь фабрику агентов на машину человека, который сидит рядом. Он в терминале и
может ответить. Инструкция ниже — для тебя; человеку соответствует [SETUP.md](SETUP.md).

Всё, что фабрика делает и почему, — в [README.md](README.md). Читать его целиком не надо,
но если человек спросит «а что это вообще» — ответ там.

## Правила

- **Токены не выдумывай и не ищи по машине.** `KAITEN_TOKEN` спрашивай у человека или
  бери из уже существующего `~/.claude/.env`. Не печатай значение токена в ответ,
  не клади его в `config.json` и никуда не отправляй.
- **`setup.py` интерактивный** — ты его запустить не сможешь: он ждёт ввода в терминал.
  Либо просишь человека запустить `python3 setup.py` самому, либо собираешь `config.json`
  сам через режимы разведки (ниже). Не пытайся кормить мастер через pipe.
- **Ничего не создавай в Kaiten молча.** Доска, колонки, карточки — только после явного
  «да» от человека.
- **Не запускай `./run.sh` без `--dry-run`**, пока человек не увидел результат холостого
  прогона и не сказал продолжать.

## Порядок

### 1. Проверить, что есть на машине

```bash
python3 setup.py --check
```

На неустановленной машине он честно скажет, чего не хватает: `claude`, `gh`, `git`,
токена, конфига. Всё, что он ругает, — это твой список задач. `gh auth login` и установку
Claude Code человек делает сам, ты только говоришь, что именно запустить.

### 2. Узнать про доски

Спроси у человека:

1. **Есть ли уже доска для фабрики?** Если нет — предложи создать: это восемь колонок
   с точными названиями, руками их заводить муторно.
2. **Нужна ли разведка инбокса?** Это отдельная доска с сырым потоком задач от команды.
   Если да — спроси, как она называется.
3. **Нужна ли привязка к долгу спринта?** Это доска эпиков, куда раз в спринт заводится
   карточка «Долг \<даты\>» с дочерними. Если да — спроси, как называется доска.
4. **Нужен ли режим эпиков?** Второй способ работы: эпик с тегом `claude:epic` проходит
   путь приёмочные критерии → апрув человека → спека → ревью спеки → сабтаски. Если да —
   спроси, где лежат эпики и на какой доске жить сабтаскам.

Три последние — необязательные. Не уговаривай: без них фабрика работает.

Про режим эпиков важно сказать человеку одну вещь, иначе он будет ждать зря: гейт там —
**блокер Kaiten**. Фабрика вешает блокер с причиной, начинающейся на `🤖`, и ждёт, пока
человек снимет его руками. Снятие блокера и есть апрув; ответа комментарием недостаточно.

### 3. Собрать конфиг

Самый простой путь — попросить человека запустить `python3 setup.py` и ответить на
вопросы. Мастер умеет создавать доску сам и спрашивает ровно то, что нужно.

Если человек просит сделать всё за него, собери `config.json` руками. Разведка — это
режимы `setup.py`, все с `--json`:

```bash
python3 setup.py --spaces "часть названия" --json   # найти пространство
python3 setup.py --boards <SPACE_ID> --json         # доски пространства
python3 setup.py --board <BOARD_ID> --json          # колонки, дорожки, id типа карточки
python3 setup.py --card-types "часть названия" --json
```

`--board` возвращает ещё и `guessed_columns` — как фабрика разложила колонки по ролям
по их названиям. Значение `null` означает «не угадалась»: такую колонку выбери сам по
списку `columns` и объясни человеку свой выбор.

Скелет бери из [`config.example.json`](config.example.json) — там все ключи с
комментариями. Обязательны только `kaiten`, `repos`, `default_repo`, `agent`, `reviewer`.
Секции `inbox`/`triager`, `sprint_debt` и `epic_flow` не нужны — **удали их целиком**,
не оставляй с нулями: фабрика проверяет наличие секции, а не значения.

У `epic_flow.subtasks.columns` роли могут делить одну колонку: на доске команды обычно
нет ни «Правок», ни «Упало». Обязательны только `queue`, `in_progress` и `agent_review` —
остальное фабрика выразит блокером.

Роли колонок (порядок в потоке карточки):

| Роль | Смысл |
|---|---|
| `queue` | фабрика берёт карточки отсюда |
| `in_progress` | агент пишет код |
| `question` | не хватило данных, ждём человека |
| `failed` | агент или обёртка сломались |
| `agent_review` | готовый PR, вход ревьювера |
| `fixes` | ревьювер вернул замечания |
| `review` | ревью пройдено, дальше человек |
| `done` | фабрика сюда не двигает |

### 4. Написать правила проекта

Это самая содержательная часть, и здесь от тебя больше всего пользы. В `project/` два
файла, оба подставляются в промпты исполнителя, ревьювера и разведчика:

- **`project/docs.md`** — какие файлы правил читать до того, как писать код;
- **`project/checklist.md`** — по какому списку исполнитель проверяет себя, а ревьювер
  ревьюит.

Не пиши их из головы. Открой репозиторий, который указан в `repos`, и посмотри, что
там есть на самом деле: `CLAUDE.md`, `AGENTS.md`, `CONTRIBUTING.md`, `docs/`, файлы
конвенций, конфиги линтеров. В `docs.md` попадает только то, что реально лежит в
репозитории — выдуманный путь агент проигнорирует, а с ним может проигнорировать
и весь список.

В `checklist.md` собери то, на чём в этом проекте реально горят: что обязательно
покрывается тестами, где нельзя ветвиться прямо в коде, что дорого по производительности,
какие практики запрещены. Опирайся на найденные файлы правил, а не на общие представления
о хорошем коде. Правило без опоры в репозитории — вкусовщина, из-за неё ревьювер начнёт
возвращать людям нормальные карточки.

Оба файла в `.gitignore`. Покажи человеку, что получилось, и попроси поправить: он знает
про свой проект то, чего в файлах не написано.

### 5. Проверить

```bash
python3 setup.py --check
```

Должно быть чисто. Доктор проверяет и доступность досок, и существование каждой колонки
по id, так что опечатка в конфиге всплывёт здесь, а не на живой карточке.

### 6. Отдать человеку

Скажи, что осталось сделать ему:

1. положить одну простую карточку в «Очередь»;
2. запустить `./run.sh --dry-run` — агент отработает по-настоящему, но в Kaiten и GitHub
   ничего не запишет;
3. посмотреть, что агент написал, и решить, продолжать ли.

Приложение в меню-баре (`./build-app.sh --install`) — потом, когда первый прогон
устроит. Без него фабрика работает из терминала.

## Если это будет публичный репозиторий

Перед коммитом:

```bash
python3 setup.py --audit
```

Аудит смотрит, что git собирается закоммитить, и ищет там id досок и пути из локального
конфига, плюс общие вещи: почты, токены, домашние каталоги. Всё, что он нашёл, надо либо
убрать из файла, либо занести в `.gitignore`. Не «объясняй» находки — чини их.
